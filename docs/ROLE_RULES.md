# 역할 및 파일 담당 규칙

## 작업 범위

현재 담당 범위는 API 명세서 기준으로 로그인, 회원가입, 온보딩, 지도 기능을 제외한 프론트엔드 기능입니다. 제외된 네 영역은 별도 담당자가 관리합니다.

## 수정 금지 영역

아래 영역의 기능 코드, UI, 스타일, 테스트, 경로, 인증 흐름은 담당자 승인 없이 수정하지 않습니다.

- 로그인·회원가입: `src/features/auth/`, `src/lib/auth/`, 관련 화면·흐름 테스트
- 온보딩 및 역할 설정: `src/features/onboarding/`, 온보딩 경로/설정 저장 로직 및 관련 테스트
- 지도: 지도 화면과 지도 전용 스타일·데이터·컴포넌트 (현재 `src/features/screens/PostOnboardingScreens.tsx`의 `map` 분기 포함)

이 저장소에서는 여러 기능이 `src/App.tsx`와 `src/features/screens/PostOnboardingScreens.tsx`에 모여 있습니다. 이 파일을 수정해야 하는 작업은 허용된 기능 분기만 제한적으로 변경하고, 위 제외 기능의 JSX·상태·스타일은 건드리지 않습니다. 공용 파일 수정이 불가피하면 변경 diff에 제외 영역의 변경이 섞이지 않도록 확인합니다.

`src/lib/api/profile.ts`에는 로그인/온보딩 흐름에서 쓰는 API도 함께 있습니다. 해당 파일 전체를 대상으로 리팩터링하지 말고, 내 레시피/저장 목록 등 담당 범위의 독립 함수만 필요한 경우 수정합니다.

## 허용 범위 예시

- 홈, 검색, 공개 레시피 목록/상세, 좋아요·저장
- 전승 기록, 음성 전사, 채팅 보완, 레시피 발행, 단계 이미지, 맛 평가
- 담당 기능의 API 타입·클라이언트 코드와 담당 파일의 목업/화면/스타일
- `docs/`에 있는 명세, 연결 현황, 개발 규칙 문서

## 공통 작업 규칙

1. API 요청은 기본적으로 `src/lib/api/client.ts`의 공통 클라이언트를 사용하고, Bearer 인증 및 공통 오류 형식을 유지합니다.
2. API 응답·요청 형식은 `docs/API_SPEC.md`와 대조합니다. 명세에 없는 API는 임의로 확정하지 말고 문서화해 백엔드 계약을 확인합니다.
3. 제외 영역을 고쳐야만 작업이 가능한 경우 임의 수정하지 말고, 필요한 파일/변경 이유를 정리해 담당자와 조율합니다.
4. 작업 후 변경 파일 목록과 diff를 확인해 제외 영역이 변경되지 않았는지 검토합니다.
